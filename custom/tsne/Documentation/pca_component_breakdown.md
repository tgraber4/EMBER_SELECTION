# PCA component breakdown

Generated by `tsne/Code/pca_loadings.py` from `tsne/PCA Output/pca.joblib` and `custom/docs/feature_index_map.json`.

**Setup:** 53 components retained, 50.16% cumulative explained variance, over 2568 scaled features.

## Output files (`tsne/PCA Output/`)

| File | Contents |
|---|---|
| `pca_top_features.csv` | Top 15 features per PC by \|loading\|: `pc, rank, index, block, field, loading, pc_variance_ratio`. Sign is kept. |
| `pca_block_contrib.csv` | Rows are PCs, columns are feature blocks. Each value is the share of that PC's squared loadings in the block (rows sum to 1 across blocks, but the file also holds `variance_ratio`). |
| `pca_feature_importance.csv` | All 2568 features ranked by variance-weighted squared loading across the 53 PCs. |

## How to read it

- A loading is the weight of a scaled feature in a component. The larger \|loading\|, the more it drives that PC. The sign only says which direction the feature pushes.
- Each PC's squared loadings sum to 1, so summing them within a block gives "what fraction of this PC is made of that block".
- `feature_index_map.json` is what turns a column index into `block` + `field`. The arrays don't store names.

## Caveats

- **Hashed features are hard to interpret.** `imports.lib_func_hashed[414]` is a hash bucket, so many different functions map to it, and it doesn't name a specific API. Hashed fields still tell you the block, just not the exact item.
- **Spread-out loadings.** Past PC1 and PC2, the top 15 features have similar loadings (about 0.06–0.08). Components are diffuse mixtures, so prefer the block-level table over single top features.
- **Importance scores are flat.** Top features in `pca_feature_importance.csv` have an importance of about 0.00075 (1/2568 is about 0.00039), so no single feature dominates.
- PCA was fit on `X_scaled` and says nothing about label relevance, only about variance.
